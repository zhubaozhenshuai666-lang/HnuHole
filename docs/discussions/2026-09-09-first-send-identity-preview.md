## 本轮调整

用户要求删除“返回编辑”，底部改成左侧“取消”、右侧“确认”，并明确确认后应回到评论界面，让用户再次点击发布。v3 保留居中、深色背景、头像与昵称布局，只调整操作区和对应流程。

| 操作 | 结果 |
| --- | --- |
| 取消 | 关闭弹框，回到原评论或回复输入界面；不确认本次身份，不发布评论，文字、图片与回复对象保留。 |
| 确认 | 保存选定的本帖身份，关闭弹框，回到原评论或回复输入界面；文字、图片与回复对象保留，评论仍未发布。 |
| 回到评论界面后，再次点击发布 | 使用刚才确认的身份发布该评论或回复，不重复弹出身份选择。 |

确认身份不触发自动发布，也不自动续跑打开弹框前的发布动作。用户可以在返回后继续修改评论。

## 保留的设计

- 尚未确认本帖身份时，首次点击评论发布入口会收起键盘并显示居中弹框；背景压暗，原回复留在背景页面。
- 头像区提供点击选择入口，以及“使用设置头像”。图中是尚未选择头像的占位图。
- 昵称输入框初始留空，右侧提供“随机昵称”；进入时不自动取名。
- 简短说明提示同帖后续发言会沿用该身份。
- 当前昵称为空，右侧“确认”暂不可用；左侧“取消”可用。

示例仍回复评论者 B，即使 B 原先回复的是 A，也不改变当前回复对象。

## 后续细化

本轮只画键盘收起的初始状态。手动输入昵称时如何适配键盘、确认后是否自动唤起键盘、头像选择方式、头像是否必选、重名与无效昵称反馈、发布中与失败状态另行细化。点击背景或系统返回的行为尚未确定。

取消与确认都会保留当前评论草稿；取消后再次打开弹框是否保留尚未确认的昵称和头像选择，以及跨页面或重新启动后的附件草稿保存范围，尚未确定。同帖身份沿用不额外决定头像日后能否修改。
