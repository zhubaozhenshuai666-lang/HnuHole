# 评论与回复 UI 评审

2026-09-20。业务主干访谈已收口，本文件记录当前页面的 UI 取舍及其业务影响；图稿评审发现业务缺口时仍须核对历史并询问，不因阶段切换而跳过。

## 已确认调整

- 用户对消息身份切换展开 v2 回复“可以，下一个”，该图入口和面板已确认。
- 用户最新要求“不用prompt”：后续直接给图，用户看图提修改，不再附 prompt。
- 用户要求取消评论与回复列表每条的“收件：松间”以及本人的收件身份小头像。两个页签只属于当前身份，不重复提示；覆盖旧 MESSAGE-IDENTITY-01 的逐条收件身份标记。
- 用户原话：“不需要收件：松间这一行的东西，因为评论与回复都是当前身份收到的回复和这个身份发出的，不需要提示吧？按我这个最新的来，如果设计里和我这个冲突，就修改一下，再问我一些问题确定设计”。
- [收到的 v1](../../UI产品图/评论与回复-收到的-v1.png)在修正前已生成，保留为旧草稿；其中逐条收件身份标记已作废，不作为最新要求或已确认稿。

## 本次业务影响核对

用户补充要求：“同等重要的是，是否修改了原来设计好的业务逻辑呢？如果修改了那就同步修改一下，缺什么信息就grill me”。

- **变更**：撤回列表逐条显示本人收件昵称／头像的展示要求，已同步至消息模块 MESSAGE-REPLIES-01 / MESSAGE-IDENTITY-01。消息首页切换入口从孤立小圆点改为显眼图标、文字和说明，已按确认的 v2 同步 MESSAGE-MASK-01。
- **业务行为未变**：收到的／我发出的继续按当前身份隔离；切换身份仍作用于整个消息页，账号级通知例外。删除身份提示不代表删除身份归属或合并各身份数据。
- **当轮关联规则**：从提醒进入原帖定位评论、继续回复使用该帖固定身份、仅清除实际查看对象未读均未变。当时保留的“我发出的”失败入口已被下文最新系统通知方案替代，重试／删除能力保留但迁移入口。
- **答复与确认范围**：用户随后答复“1. 不用 / 2. 是 / 3. 推荐”，确认以下三项排版规则；不表示自动确认新增点击行为或尚未评审的 v2 图稿。旧 v1 不能当作最新规范。
- **后续维护**：每轮 UI 修改同时核对业务影响；已确认的行为变化同步模块与交接，有缺口先排重后提问。保留历史稿用于追溯，不改写历史答复。

## 三个 UI 问题与答复（已确认）

1. 顶部“当前身份 · 松间”是否也去掉？建议去掉，顶部只留返回、页面标题及两个页签；身份在消息首页选择后带入，不在子页重复提示。
2. “收到的”每条是否展示对方头像？建议在发言者昵称左侧放一个小头像，表达是谁回复；它与已取消的本人收件头像不同。
3. 长回复预览展示多少？建议最多两行，超出省略；来源帖标题一行，点击记录仍按已有规则进入原帖定位具体评论。这里只决定预览密度，不重新询问跳转行为。

用户依次答复“1. 不用 / 2. 是 / 3. 推荐”：页头不显示当前身份；收到的展示对方头像；正文最多两行、超出省略，来源标题一行。三项同步 MESSAGE-REPLIES-01。

[收到的 v2](../../UI产品图/评论与回复-收到的-v2.png)已通过内置 image_gen 编辑生成并保存；目视核对页头及逐条收件标记均已删除，四条记录均有对方头像，首条示范两行截断、来源标题单行，保留原页签和未读状态。用户随后确认“这次修改的挺好的，按修改后的图来，进行下一个设计”，收到的 v2 定稿；未实现客户端交互。

## 新增头像后的交互问题（已确认）

Q1：收到的列表中，点击对方头像／昵称，也进入原帖对应评论，还是直接进入私信？

建议整条（含头像／昵称）都进入原帖对应评论；需要私信时，在原帖点击发言者头像／昵称。用户答复“1. 按推荐”，已同步 MESSAGE-NAV-01 与 CONTACT-01 的适用范围说明。

排重依据：MESSAGE-NAV-01 已确认提醒进入原帖定位评论；CONTACT-01 仅明确帖子或评论上的头像昵称直达私信，尚未定义消息提醒列表内新头像的独立点击行为。只询问新增区域，不重新询问已定的整条提醒跳转或首次私信限制。本题不影响静态排版出图。

### 迁移后的两项（已确认）

1. 点击顶部提示后，直接打开系统通知里的该条失败详情，还是先到通知列表？建议直接打开对应失败详情，显示原内容、目标及重试／删除；返回进入系统通知列表。若当前消息身份不同，沿用现有通知导航切到任务所属身份，不换发送归属。
2. 重试成功或主动删除失败任务后，该条失败通知是否保留？建议移除该失败通知，成功记录在“我发出的”查看；删除则放弃该任务且不留可恢复入口。进入或阅读通知本身不执行移除。

用户答复“1. 推荐 / 2. 推荐”，两项均确认并同步消息／评论模块：顶部提示直达失败详情；重试成功或主动删除后移除失败通知。不得重问，也不再问失败项在“我发出的”如何排序。
