# 仓库、认证与首条垂直切片

状态：accepted（2026-09-23）。项目使用单仓库 monorepo，包含 Flutter 客户端、Go 模块化单体、OpenAPI 契约、基础设施和文档；首版目标可能超过 10000 名用户，但用户规模不决定仓库拆分，运行时扩展由服务端部署、数据库和后续容量设计负责。数据库迁移使用 `goose`，OpenAPI 使用 `oapi-codegen`；登录采用服务端不透明会话令牌；本地开发由宿主机运行 Flutter/Go，Docker Compose 运行基础设施。第一条垂直切片验证文字内容主链，私信作为后续切片。

## 工程边界

- 初始仓库目录为 `apps/mobile`、`services/api`、`packages/openapi`、`infra` 和 `docs`；Go 服务端内部继续按领域模块组织。
- `goose` 迁移文件和 OpenAPI 源文件进入版本控制；不使用运行时自动建表。
- 邮箱验证码继续由隔离验证边界处理；隐私认证的独立服务和稳定匿名凭证边界见 [ADR 0005](0005-privacy-preserving-email-authentication.md)，社区业务服务只接收隐私协议产生的稳定匿名凭证，不接收邮箱或邮箱—账号映射。会话记录由社区服务保存，令牌仅存于客户端系统安全存储，服务端支持设备替代、注销和封禁时立即撤销。
- 开发环境首阶段使用 PostgreSQL 与 Mailpit；CI、集成测试和部署基线见 [ADR 0004](0004-ci-testing-email-and-deployment.md)。图片对象存储和生产推送不进入第一条文字切片。

## 首条垂直切片验收范围

开发邮箱验证夹具登录、身份初始化、进入导航树和通道、发布文字帖子、阅读详情、发布主评论与楼中楼回复、在“我的”查看帖子和草稿，并验证帖内身份固定、不同身份隔离、API/迁移/OpenAPI 生成和基础测试可运行。开发夹具提供两个测试账号：账号 A 有两个身份，账号 B 有一个身份，用于验证同账号身份隔离和帖内身份固定。首条切片直接实现基础导航树，拆为两次开发任务；自定义 `#标签` 仅保留可选字段，暂不实现输入、复用和筛选交互。已发布帖子、评论、身份和通道归属须在 PostgreSQL 中持久化，本机草稿须在 Drift/SQLite 中持久化并可在重启后恢复，不要求首条切片做跨设备草稿同步。私信发送、实时聊天、图片、推送、热榜、举报和申诉安排到后续切片。

## 下一条认证垂直切片

邮箱输入、发送验证码、Mailpit 收信、验证码验证、账号自动创建/恢复、服务端不透明会话建立、有效会话恢复、主动退出和登录后通道节点显示组成下一条认证切片。首次验证不自动创建公开身份；无身份账号可以浏览导航树和通道内容，首次需要公开发言时再进入基础身份设置。认证仍必须经过真实邮箱验证码流程，开发验证适配器只读取测试验证码，不提供万能码或绕过入口。

### 认证接口与本地状态边界（2026-09-23；隐私认证前置门槛见 ADR 0005）

- 认证主链预定使用四个客户端接口：`POST /api/v1/auth/verification-requests`、`POST /api/v1/auth/verification-confirmations`、`GET /api/v1/auth/session` 和 `DELETE /api/v1/auth/session`；通道目录仍使用 `GET /api/v1/channels`。完整邮箱只在独立验证方处理；社区服务只接收隐私协议产生的稳定匿名凭证，不接收邮箱或由验证方传来的账号映射。跨组织的内部协议接口和调用顺序尚未设计。
- 服务端会话令牌采用不透明值，客户端只存系统安全存储；服务端保存会话、设备和撤销状态。新设备成功验证后原设备会话立即失效，原设备下一次受保护请求以 `401` 和 `session_replaced` 返回。
- 客户端区分恢复失败原因：`401` 清除令牌和导航节点并回到邮箱入口，但保留账号归属草稿和本地文件；`503` 或超时保留令牌和本地状态并提供重试，不误判为退出。恢复成功后必须重新请求并校验完整通道目录。
- 主动退出只撤销会话并清除安全存储令牌，不删除本机草稿；草稿按内部账号隔离，原账号重新登录后恢复，其他账号和未登录状态不可见。
- 认证错误使用 `401`、`422`、`429`、`503` 及机器可读错误码；请求编号不得包含邮箱或验证码。格式、域名合规的验证码申请对新旧邮箱返回相同受理状态和通用提示，账号仅在验证码验证成功后创建或恢复。验证码申请和确认使用客户端幂等键去重，重复请求核对原结果，不重复发码、建号或建会话；幂等键只在本服务操作范围内使用，不能跨方转发，双方不得共享可精确关联的日志、备份和关联编号。投递未知时第 40 秒先用原幂等键核对状态，只有确认未发出才允许新请求重发并重置六十秒间隔。跨组织协议的一致性、失败处理和抗时间关联另行设计。会话剩余七天以内且用户活跃时静默续期三十天；主动退出和设备接替仍立即撤销。

认证主链实现有前置门槛：必须先完成 ADR 0005 所定义的双组织隐私协议、安全评审、跨服务日志/幂等隔离设计和独立主体运营安排。尚未满足时，不得用单方 HMAC、邮箱匹配表或人工恢复实现登录账号映射。

### 首条切片的两次开发任务

1. **通道目录与基础导航树**：通过服务端数据库种子数据建立七个固定通道，并提供稳定的通道 ID 与目录接口；未登录时只显示树的入口外壳，不显示通道节点，邮箱验证成功后加载并显示节点。客户端实现登录后的高质量二维功能树。树初始展示“吐槽、避雷、安利、搭子、情感”五个通道，另外两个通道（“互助”“科技”）可通过拖动探索到达。拖动、层次变化、节点点击反馈、不同屏幕尺寸适配和返回位置恢复属于本任务；不实现真实三维、热度排序、搜索或最终视觉定稿。
2. **导航树接入文字内容主链**：从树节点进入对应通道列表，接入文字帖子发布、详情阅读、主评论、楼中楼回复、“我的”帖子与草稿，并验证每帖单通道归属、帖内身份固定、不同身份隔离和重启后的服务端/本机持久化。热度、搜索和标签筛选仍不在首条切片内。

服务端数据库是通道目录的唯一业务来源；登录后通过 `GET /api/v1/channels` 返回完整七项通道，每项包含 `id`、不可变英文 `code`、显示名称、初始展示标记和稳定排序，客户端根据屏幕尺寸计算节点位置、缩放和层次。首版固定编码和冷启动元数据为：`vent`/10/true、`warning`/20/true、`recommendation`/30/true、`buddy`/40/true、`emotion`/50/true、`mutual_help`/60/false、`technology`/70/false。客户端不维护另一份可变通道业务清单；接口不可用时只显示入口外壳、加载或重试状态，不以本地旧目录冒充当前业务数据。通道的增删改管理不属于这两次任务。

目录接口只在完整数据成功时返回 `200`；无效会话返回 `401`，服务暂不可用返回 `503`，错误响应带机器可读错误码和请求编号。树的拖动位置只在本次登录使用期间保留，从通道返回树时恢复；App 进程重启或重新登录后使用固定初始布局，不把该临时视图状态写入服务端或本机业务库。

任务 1 的自动化验收分为四层：迁移/种子验证恰好七个通道、英文 `code` 和 UUID 唯一且重复执行不重复插入；API 验证未登录未授权、登录后返回完整七项及五项初始标记；客户端加载验证未登录无节点、成功后显示五项、失败不显示部分节点且重试可恢复；交互验证拖动可到达另外两项、点击进入正确通道、返回后恢复位置。

任务 1 的手工验收和端到端测试必须经过真实邮箱验证与会话建立；Mailpit 和开发验证适配器只提供测试取码能力。数据库迁移只建表并写入七个通道种子，账号 A（两个身份）和账号 B（一个身份）由仅开发/测试环境可运行的夹具命令或集成测试初始化器创建，不写入生产迁移。`packages/openapi` 中的 OpenAPI 源文件是目录接口唯一契约，生成的 Go 类型/接口必须由 CI 检查无漂移。
